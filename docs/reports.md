# Отчеты, CSV-выгрузка и report-service

## 1. Отчет «Сдаваемость и просрочки» и «Текущие результаты»

`GET /api/v1/courses/:id/report?from=YYYY-MM-DD&to=YYYY-MM-DD` — только преподаватель-владелец курса.

| Параметр | Правило |
|---|---|
| Дата отбора | срок сдачи задания (`dueAt`) попадает в период. `from` и `to` — календарные даты по Алматы, обе включительно |
| Период | не длиннее 90 дней. По умолчанию — 60 дней назад и 29 дней вперед от сегодняшнего дня |
| Статусы | задания `published`. Студенты — только с действующим зачислением (`active`) |
| Отмены | отчисленные студенты (`removed`) и их сдачи в отчет не входят. Записи в базе сохраняются |
| Исправления | новая версия работы не создает «вторую сдачу»: факт = пара студент–задание. Переоценка учитывается автоматически: берется оценка последней оцененной версии |
| Единица | студенты (для сдаваемости) и целые баллы (для результатов) |

**Формулы по заданию:**
- `Сдали` = студенты, у которых есть хотя бы одна версия.
- `Вовремя` = есть хотя бы одна версия с `isLate = false` (ровно в срок — вовремя).
- `Только с опозданием` = сдали, но все версии с опозданием.
- `Не сдали` = студенты − сдали. `Пропустили срок` = не сдали, а срок уже прошел.
- `Сдаваемость` = сдали / студенты × 100, один знак после запятой.

**Формулы по студенту:**
- `Баллы` = сумма текущих оценок по заданиям периода.
- `Результат` = баллы / сумма `maxScore` заданий периода × 100.

**Итог курса:**
- `Сдаваемость` = все сдачи / (задания × студенты) × 100.
- `Средний результат курса` = сумма баллов всех студентов / (студенты × сумма `maxScore`) × 100.

**Нулевой результат:** нет заданий или студентов — счетчики 0, проценты «—» (`null`, а не `NaN`).

### Ручной расчет (4 факта)

Студенты s1, s2, s3. Задание A: макс. 10, срок прошел. Задание B: макс. 20, срок впереди.

| Факт | Задание | Студент | Версии | Вовремя | Текущая оценка |
|---|---|---|---|---|---|
| 1 | A | s1 | 1 | да | 8 |
| 2 | A | s2 | 2 | нет (обе поздно) | 6 |
| 3 | B | s1 | 1 | да | — |
| 4 | B | s3 | 1 | да | 15 |

| Задание | Студентов | Сдали | Вовремя | Только поздно | Не сдали | Пропустили | Сдаваемость |
|---|---|---|---|---|---|---|---|
| A | 3 | 2 | 1 | 1 | 1 (s3) | 1 | 2/3 = 66,7% |
| B | 3 | 2 | 2 | 0 | 1 (s2) | 0 — срок не прошел | 66,7% |
| **Итого** | 6 ожид. | 4 | 3 | 1 | 2 | 1 | 4/6 = 66,7% |

| Студент | Баллы | Результат (из 30) |
|---|---|---|
| s1 | 8 | 26,7% |
| s2 | 6 | 20,0% |
| s3 | 15 | 50,0% |

Средний результат курса = (8 + 6 + 15) / (3 × 30) = 29 / 90 = **32,2%**.

Этот же пример проверяет unit-тест `api/test/unit/report-calc.spec.ts`. Результат в браузере должен совпасть с ним на таких же данных.

### Почему агрегация MongoDB + расчет в JavaScript

- **Агрегация** (`$match → $addFields → $sort → $group`) сворачивает все версии в одну строку на пару студент–задание прямо в базе. В приложение приходит не больше «студенты × задания» строк, а не все версии с текстами.
- **Остальное считается в JavaScript** чистой функцией `buildCourseReport`: несдавшие (их нет в коллекции сдач), проценты, итоги. Объем ограничен (до 200 заданий и 2000 студентов). Функция покрыта unit-тестом на ручном примере.

## 2. Средний балл по заданиям (report-service)

`GET /api/v1/courses/:id/report/summary` — тот же период и те же права.

1. Основной API проверяет права и собирает не больше 5000 **обезличенных** фактов `{ group: id задания, value: текущий балл }`. Студентов, текстов и паролей в фактах нет.
2. Отправляет их в `POST {REPORT_SERVICE_URL}/summary` с заголовком `X-Internal-Key`, ждет не дольше 3 секунд.
3. Сервис возвращает по каждой группе `count`, `total`, `average` (2 знака). API добавляет названия заданий и средний процент.
4. Любой сбой сервиса (остановлен, таймаут, неверный ключ, неверный формат ответа) — `503 REPORT_SERVICE_UNAVAILABLE` **только для этого отчета**. Сайт, основной отчет и все команды продолжают работать.

Ручной пример: A → оценки 8 и 6 → `count 2, total 14, average 7`. B → 15 → `count 1, total 15, average 15`.

### Контракт report-service

| Маршрут | Вход | Ответ |
|---|---|---|
| `GET /health` | — | `200 { status: "ok" }` |
| `POST /summary` | заголовок `X-Internal-Key`, тело `{ facts: [{ group: string, value: number }] }` | `200 { items: [{ group, count, total, average }], factsCount }` |

Проверки сервиса:
- внутренний ключ (сравнение за постоянное время), иначе `401`;
- только поля `group` и `value`, `group` — непустая строка до 200 символов;
- `value` — конечное число (`NaN`, `Infinity`, строки отклоняются);
- не больше 5000 фактов;
- ошибки в формате `{ error: { code, message } }`.

Границы сервиса:
- не пишет в основную базу и вообще не подключается к ней;
- не получает пароли и закрытые тексты;
- CORS-заголовков нет, по умолчанию слушает только `127.0.0.1` — браузер к нему не обращается.

**Проверка остановленного сервиса:** остановить report-service (Ctrl+C) и обновить страницу отчета. Блок «Средний балл» покажет ошибку и кнопку «Повторить», остальные таблицы отчета на месте. Студент при этом может сдать работу.

## 3. CSV-выгрузка

`GET /api/v1/reports/export.csv?courseId=...&from=...&to=...` — журнал всех версий работ курса, сданных за период (дата отбора — время сдачи). Только действующие студенты.

| Колонки |
|---|
| Курс; Задание; Срок (Алматы); Студент; Версия; Сдано (Алматы); С опозданием; Оценка версии; Макс. балл |

- **Формат.** UTF-8 с BOM и разделитель `;`, чтобы Excel с русской локалью сразу открыл файл с колонками.
- **Проверки до заголовков.** Права и период проверяются до отправки заголовков, ошибка приходит обычным JSON.
- **Поток.** Строки читаются курсором MongoDB (`batchSize 200`) через асинхронный генератор и `stream.pipeline` в HTTP-ответ. Файл не собирается в памяти целиком.
- **Backpressure.** `pipeline` не берет следующую строку из курсора, пока ответ не готов принять данные.
- **Разрыв соединения.** Если клиент оборвал загрузку, `pipeline` останавливается, курсор закрывается. Второй JSON после отправленных заголовков не отправляется: соединение просто закрывается.
- **Экранирование.** Значение с `;`, кавычкой или переводом строки берется в кавычки, кавычки удваиваются.
- **Нейтрализация формул.** Значение, начинающееся с `=`, `+`, `-`, `@`, табуляции или перевода строки, получает апостроф в начале. Excel показывает его как текст, а не выполняет формулу.

## 4. Где нужна последовательность, а где Promise.all

- **Последовательно.** Шаги внутри транзакций (зачисление → номер версии → вставка; обновление работы → запись оценки): каждый шаг зависит от предыдущего и должен идти в одной сессии. Проверки прав идут до изменения данных и до отправки CSV-заголовков.
- **Параллельно (`Promise.all`).** Только независимые чтения ограниченного объема: страница списка и `countDocuments`, задания и зачисления курса для отчета.
- **Без блокировки Node.js.** Большие наборы (CSV) идут потоком по курсору, а не массивом в памяти. Расчеты отчета работают с ограниченным набором уже свернутых фактов.
