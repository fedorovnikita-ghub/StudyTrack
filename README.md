# StudyTrack — учет учебных заданий и результатов

Учебный проект по дисциплине «Веб-программирование на JS» (ТЗ №06).

Преподаватель создает курсы и задания и зачисляет студентов. Студент сдает текст работы, каждая сдача сохраняется новой версией. Преподаватель оценивает конкретную версию. Текущий результат считается по последней оцененной версии, прежние оценки сохраняются. Просроченные сдачи помечаются.

## Подготовка MongoDB Atlas

1. Создать кластер (подходит бесплатный M0) и пользователя базы в разделе Database Access.
2. В Network Access разрешить свой IP-адрес.
3. Скопировать строку подключения (Connect → Drivers) и указать в конце имя базы:
   - рабочая база: `.../studytrack?retryWrites=true&w=majority`
   - тестовая база: `.../studytrack_test?retryWrites=true&w=majority` (понадобится для тестов)

Кластер Atlas всегда работает как replica set, поэтому многодокументные транзакции доступны без дополнительной настройки.

## Пользователи и роли

| Роль | Как появляется | Что может |
|---|---|---|
| Студент | регистрация на сайте | свои курсы, сдача работ, свои результаты |
| Преподаватель | только защищенной командой или seed | свои курсы, зачисления, задания, оценки |

Регистрация всегда создает студента. Поле `role` в запросе регистрации отклоняется с ошибкой 400.

Создать преподавателя (в папке `api`). Команда по очереди спросит email, имя, роль и пароль:

```bash
npm run user:create
```

### Вход

- `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `POST /api/v1/auth/logout`, `GET /api/v1/auth/me`.
- Пароль не короче 10 символов и не длиннее 72 байт в UTF-8: дальше bcrypt не учитывает символы. Хранится только bcrypt-хеш, пароль не пишется в лог.
- При неверном email или пароле приходит одно общее сообщение. Время ответа не выдает, существует ли email.
- JWT живет 60 минут и хранится только в памяти вкладки. После обновления страницы нужно войти снова, как допускает ТЗ.
- Выход очищает токен на клиенте. Сервер токены не хранит, поэтому выданные копии JWT не отзываются, они просто истекают.
- Каждый защищенный запрос проверяет токен и заново читает пользователя из базы. Поэтому отключение аккаунта или смена роли действуют сразу.
- Все маршруты закрыты по умолчанию (глобальный guard). Открытые помечены `@Public()`.

Примеры запросов: [docs/http/auth.http](docs/http/auth.http), [docs/http/courses.http](docs/http/courses.http), [docs/http/submissions.http](docs/http/submissions.http), [docs/http/grades.http](docs/http/grades.http).

## Автотесты

Тесты используют **отдельную базу** из `MONGODB_URI_TEST` (например, `studytrack_test` на том же кластере Atlas). Если имя базы не оканчивается на `_test`, тесты не запустятся: они очищают документы своей базы перед каждой проверкой. Индексы сохраняются.

```bash
cd api
npm test                  # все тесты
npm run test:unit         # только unit
npm run test:integration  # только HTTP с тестовой MongoDB
```

| Файл | Тип | Что проверяет | Заглушки |
|---|---|---|---|
| `test/unit/submission-rules.spec.ts` | unit, 4 | номер версии, граница срока (ровно в срок — вовремя), предел версий, длина текста | нет: чистые функции. Не проверяют работу с базой |
| `test/unit/grade-rules.spec.ts` | unit, 5 | диапазон балла, «последняя оцененная версия», оценка 0, проценты | нет: чистые функции. Не проверяют работу с базой |
| `test/integration/auth.spec.ts` | HTTP + MongoDB, 4 | регистрация без роли и хеша, нормализация email, 409 на дубликат, одно сообщение 401 | нет |
| `test/integration/access.spec.ts` | HTTP + MongoDB, 5 | 401/403/404, чужой курс и чужая работа без утечки текста, потеря доступа после отчисления, 400 на неверный id | нет |
| `test/integration/main-flow.spec.ts` | HTTP + MongoDB, 4 | основной путь сдачи и оценки, текущий результат, ошибки полей без записи, 409 по version, просрочка и предел версий | срок в прошлом задается прямо в базе: через API его задать нельзя |
| `test/integration/realtime.spec.ts` | Socket.IO + HTTP + MongoDB, 2 | события доходят автору и преподавателю, но не постороннему. В событии нет текста и баллов. Неверный токен отклоняется | нет: настоящий Socket.IO-клиент |
| `test/integration/concurrency.spec.ts` | HTTP + MongoDB, 3 | 5 одновременных сдач → номера 1..5, две одновременные оценки → одна запись, два зачисления → одно действующее | нет |

Интеграционные тесты поднимают настоящий `AppModule` с той же настройкой, что в `main.ts` (`src/app.setup.ts`), и проверяют итоговые документы в базе, а не только HTTP-коды. Преподаватель в тестах создается прямо в базе: через сайт эту роль получить нельзя.

## REST API

Все маршруты имеют префикс `/api/v1`. Списки возвращают `{ items, page, limit, total }`: по умолчанию `page=1`, `limit=20`, максимум `limit=100`. Неизвестные поля в теле и параметрах запроса отклоняются с ошибкой 400.

| Маршрут | Доступ | Действие |
|---|---|---|
| `GET /categories` | любой вошедший | справочник категорий (`includeArchived=true` — с архивными) |
| `POST /categories` | преподаватель | создать категорию (`name`, `parentId`) |
| `POST /categories/:id/archive` | автор категории | архивировать категорию без курсов и действующих подкатегорий |
| `DELETE /categories/:id` | автор категории | удалить категорию, в которой никогда не было курсов и нет подкатегорий (204) |
| `GET /courses` | любой вошедший | мои курсы: преподавателю свои, студенту те, куда он зачислен. Фильтры `search`, `categoryId`, `status` |
| `POST /courses` | преподаватель | создать курс |
| `GET /courses/:id` | владелец или зачисленный студент | карточка курса |
| `PATCH /courses/:id` | владелец | изменить курс, обязательно поле `version` |
| `POST /courses/:id/enrollments` | владелец курса | зачислить студента по email |
| `GET /courses/:id/enrollments` | владелец курса | студенты курса (`status=active\|removed`, `search`) |
| `POST /courses/:id/enrollments/:enrollmentId/remove` | владелец курса | отчислить, обязательна причина `reason` |
| `POST /courses/:id/assignments` | владелец курса | создать задание: `title`, `text`, `dueAt` (ISO 8601 с часовым поясом), `maxScore`, `settings` |
| `GET /courses/:id/assignments` | владелец или зачисленный студент | задания курса по сроку. Студенту также сводка его сдач |
| `GET /assignments/:id` | владелец или зачисленный студент | карточка задания |
| `POST /assignments/:id/submissions` | зачисленный студент | новая версия работы (`text`) |
| `GET /assignments/:id/submissions` | студент — свои версии; владелец — все работы | история версий / работы задания (`status`, `studentId`) |
| `GET /submissions/:id` | автор или преподаватель курса | полный текст версии и история ее оценок |
| `POST /submissions/:id/grade` | преподаватель курса | оценка версии: `score`, `comment`, `version` |
| `GET /grading/queue` | преподаватель | кабинет оценивания: работы всех своих курсов (`status`, `courseId`) |
| `GET /results/my` | студент | личные результаты по курсам |

Чужой курс отвечает `404`, действие не своей роли — `403`, запрос без входа — `401`.

### Принятые граничные правила

Одинаковы на клиенте и сервере:

- Категориями управляют преподаватели. Свою категорию автор может удалить, только если с ней ничего не связано: курсов никогда не было, подкатегорий нет. Связанную категорию можно только архивировать (ТЗ: «архивирование либо понятный отказ, сохраняя историю»).
- Сдача работы ровно в момент срока считается вовремя. Просроченной считается сдача позже срока (`submittedAt > dueAt`). Время сдачи ставит сервер.
- Срок задания при создании должен быть в будущем и не дальше двух лет. Форма принимает время Алматы и отправляет его на сервер в UTC.
- Номер версии назначает сервер: 1, 2, 3… внутри пары студент–задание. Предел версий задается в `settings.maxVersions` (1–50, по умолчанию 20). Сверх предела ответ `409 MAX_VERSIONS_REACHED`.
- Минимальная длина текста работы задается в `settings.minTextLength` (по умолчанию 1). Максимум — 20000 символов.
- Балл — целое число от 0 до `maxScore` задания включительно. Оценить можно любую версию, в том числе повторно: каждая оценка — новая запись в `grades`.
- **Текущий результат** по заданию — оценка последней оцененной версии (наибольший номер среди оцененных). Новая неоцененная версия результат не обнуляет. Итог курса — сумма текущих результатов из суммы `maxScore` всех заданий курса.
- Оценка передает `version` работы. Если работу уже оценили в другом окне, приходит `409 VERSION_CONFLICT`, и результат не перезаписывается.
- Отчисленный студент теряет доступ к курсу, заданиям и своим работам сразу. Его записи сохраняются.
- Неверный формат id в адресе дает `400 INVALID_ID`. Корректный, но несуществующий или чужой id дает `404`.

## Реальное время (Socket.IO)

Socket.IO работает на том же порту, что и API. Клиент передает JWT в `handshake.auth.token`. Сервер проверяет его так же, как для REST, и сам кладет сокет в личную комнату `user:<id>`. Клиент не выбирает подписки, поэтому получить чужие события нельзя.

| Событие | Когда | Кому | Содержимое |
|---|---|---|---|
| `submission.created` | после успешной транзакции сдачи | автору работы и преподавателю курса | `submissionId`, `assignmentId`, `courseId`, `studentId` |
| `grade.changed` | после успешной транзакции оценки | владельцу работы (если он все еще зачислен) и преподавателю | те же id, без балла и текста |

- События содержат только id и тип. Актуальные данные экран всегда перечитывает через REST: источник правды — API.
- Доставка каждого события не гарантируется. После переподключения сайт перечитывает данные открытого экрана.
- В шапке видно состояние соединения: «онлайн», «подключение…», «нет связи, переподключаемся».
- Выход закрывает Socket. По истечении JWT сервер сам закрывает соединение. Отключенному аккаунту события не отправляются, его соединения закрываются.
- Ошибка отправки события не отменяет сохраненную сдачу или оценку.

**Ручная проверка обрыва и восстановления:**
1. Откройте кабинет оценивания преподавателя и страницу задания студента в двух профилях браузера.
2. Остановите API (Ctrl+C). В шапке появится «нет связи, переподключаемся».
3. Запустите API снова. Индикатор вернется в «онлайн», списки перечитаются с сервера.
4. Студент сдает работу: она появляется в кабинете оценивания без обновления страницы.
5. Преподаватель ставит оценку: она появляется в истории версий студента.

## Формат ошибок API

Все ошибки возвращаются в одном формате:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "Проверьте правильность заполнения полей", "fields": { "title": "..." } } }
```

| Код HTTP | Когда |
|---|---|
| 400 | неверный формат или ошибка валидации, лишние поля |
| 401 | нет входа |
| 403 | действие запрещено для роли |
| 404 | объекта нет, или он чужой |
| 409 | конфликт состояния, уникальности или версии |
| 503 | временно недоступна база или сервис отчетов |
| 500 | неожиданная ошибка (без технических подробностей) |
